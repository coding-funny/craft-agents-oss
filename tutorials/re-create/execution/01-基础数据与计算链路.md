## 实现步骤

### E00：建立独立包和测试入口

1. 创建 `@craft-agent/commerce-agent` workspace 包。
2. 复用仓库已有 TypeScript 与测试基础设施，不引入另一套构建系统。
3. 添加根级命令：

```bash
bun run commerce:typecheck
bun run commerce:test
```

4. 先放置最小占位测试，证明新包能被 workspace 发现。

### E01：冻结领域契约

至少定义：

- `TimeRange`、`Money`、`ProductRef`
- `SalesRecord`、`InventorySnapshot`、`PromotionRecord`、`AdRecord`
- `ToolEnvelope<T>`、`EvidenceRef`、`MetricValue`
- 统一错误码：`INVALID_ARGUMENT`、`NOT_FOUND`、`UPSTREAM_TIMEOUT`、`RATE_LIMITED`、`INTERNAL`

契约必须满足：

- 金额统一使用整数最小货币单位，禁止浮点金额；
- 时间统一为带时区的 ISO 8601；
- SKU、商品、店铺和活动 ID 不混用；
- 所有工具结果带 `source`、`as_of`、`query`、`trace_id`；
- 证据引用可定位到文件、记录或外部结果片段。

### E02：构建固定样例数据与适配器

1. 构建至少三类可解释案例：

   - 销量下降且库存不足；
   - 促销拉升 GMV 但毛利下降；
   - 广告消耗增加但转化率下降。

2. 数据中同时包含退款、取消单、零销量 SKU、多个币种或明确的单币种约束。
3. `FixtureAdapter` 只负责读取和筛选原始数据，不负责生成诊断结论。
4. 所有查询均显式接收 `TimeRange` 和业务过滤条件。

### E03：建立证据仓库

1. 每次适配器查询生成稳定的 `evidence_id`。
2. 保存工具名、参数、时间窗、原始来源、内容摘要和 Trace。
3. 提供按 `evidence_id` 读取详情的接口。
4. 对同一输入生成可复现引用，避免报告引用随机变化。

### E04：实现确定性指标

至少实现：

- GMV、订单量、销量、退款额、净销售额；
- 库存覆盖天数、缺货 SKU 数、潜在缺货损失；
- 促销前后销量、GMV、毛利率变化；
- 广告消耗、CTR、CVR、ROAS；
- 毛利额、毛利率以及退款后的贡献毛利。

边界规则必须写进代码和测试：

- 除零返回 `null` 或显式不可计算状态；
- 缺字段不默认为零；
- 时间窗口使用半开区间还是闭区间必须统一；
- 多币种数据不得直接相加；
- 退款与取消单的口径必须固定；
- 舍入策略必须可测试。

## 强制测试

- 时间窗口边界与时区；
- 空数据、零分母、缺字段；
- SKU 与商品 ID 映射；
- 退款、取消单与重复记录；
- 金额精度和多币种保护；
- 同一查询的证据引用稳定性；
- 三个业务案例的指标结果为固定值。

- 新包可独立 typecheck 和 test；

- 固定样例可以稳定算出预期指标；
- 所有关键指标都能返回至少一个 `EvidenceRef`；
- 测试覆盖上述所有边界；
- `packages/commerce-agent/demo/progress.md` 已记录本链路文件、命令结果和遗留问题。
