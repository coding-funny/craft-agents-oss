# 链路 3：诊断与报告

## AI 任务

在只读工具之上实现可复现的经营诊断 Skill，完成销量、库存、促销、广告联合分析，并以结构化 Artifact 输出报告。报告必须经过证据、来源和完整性门禁，不能只生成一段自然语言。

## 必读输入

- [链路 2：MCP 与宿主接入](./02-MCP与宿主接入链路.md)
- `tutorials/01-电商Agent改造计划.md` 中诊断流程与报告要求
- `tutorials/02-电商数据工具与审批契约.md`
- 仓库内已有 Skill 格式、Artifact 创建方式和会话消息处理实现
- `packages/commerce-agent/demo/progress.md`

- Trace、Evidence 和 Tool Envelope 已稳定；
- Source 默认权限只读；

## 实现步骤

### E08：实现经营诊断 Skill

Skill 必须把流程约束写清楚：

1. 先确认店铺、商品范围、时间窗、比较基线与币种。
2. 调销量工具识别异常维度，不凭提示词预设根因。
3. 根据异常调用库存、促销和广告工具补证据。
4. 区分事实、推断、建议和未知信息。
5. 每个关键结论至少引用一个 `evidence_id`。
6. 证据冲突时保留冲突并降低置信度，禁止强行得出单一结论。
7. 建议不得自动变成执行动作。

Skill 必须显式绑定：

- `skillSlugs`
- `requiredSources`
- 工具白名单
- 报告 Artifact schema

### E09：完成广告联合诊断

1. 将广告数据接入同一时间窗口和商品维度。
2. 支持 CTR、CVR、CPC、ROAS 与销售转化的联合判断。
3. 处理广告归因窗口与销售窗口不一致的问题。
4. 对缺失广告归因数据返回“证据不足”，不伪造关联。
5. 至少覆盖：

   - 花费增加、转化下降；
   - 点击增长、库存不足导致成交受限；
   - 广告正常但自然流量下降；
   - 归因数据缺失。

### E10：实现报告 Artifact 与质量门禁

报告至少包含：

- `report_id`、`trace_id`、分析范围和生成时间；
- Executive Summary；
- 核心 KPI 与基线对比；
- 异常现象；
- 根因假设、置信度与反证；
- Evidence 列表；
- 风险与未知项；
- 建议动作；
- 如存在高风险动作，仅输出提案草稿，不得执行。

`validateReport` 至少检查：

- 必填章节是否存在；
- 每个关键结论是否有 Evidence；
- Evidence 是否可解析；
- 指标单位、币种、时间窗是否一致；
- 建议与事实是否混写；
- 是否存在未经证据支持的确定性措辞；
- Artifact 是否已成功持久化并能重新读取。

消息发送完成不代表任务完成。必须以可读取的 `report_id` 和通过校验的 Artifact 作为完成信号。

## 强制测试

- 三类固定样例分别生成符合 schema 的报告；
- 缺 Evidence 的报告被拒绝；
- 不存在的 Evidence ID 被拒绝；
- 币种或时间窗口冲突被拒绝；
- 广告归因缺失时输出低置信度或证据不足；
- Artifact 写入后可按 `report_id` 读取；
- 同一固定输入的关键指标和引用稳定；
- Skill 未加载或 Source 缺失时明确失败。

## 完成门槛

- 真实宿主会话可以通过 Skill 调用多工具完成诊断；
- 三类案例均生成可读取的结构化报告；
- 所有关键结论均能追溯到 Evidence 和 Trace；
- 报告门禁能拒绝缺证据、缺来源、单位冲突和持久化失败；
- 诊断流程不包含审批或执行副作用；
- 进度文档已记录三个报告 ID、Trace ID、命令结果和已知局限。

## 禁止事项

- 不把固定案例答案写进 Prompt；
- 不把模型自然语言当作唯一报告产物；
- 不让报告渲染器偷偷补齐不存在的证据；
- 不将相关性描述为已证明因果；
- 不创建真实平台操作；
- 不以 `sendMessage` 已接受作为完成条件。
