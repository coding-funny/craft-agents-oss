# 06：运营交互与业务反馈链路

状态：PLANNED。产物类型：Workflow / Memory / Agent supporting。目标是让不读源码的运营用户完成调查、核查、审批和反馈，并形成 Monitor → Detect → Investigate → Decide → Act 的可见闭环。

## 1. 必读输入与进入条件

读 [入口](./README.md)、[共享契约](./00-总体设计与共享契约.md)、[03](./03-身份授权与审批治理链路.md)、[04](./04-持久任务与可靠执行链路.md)、[05](./05-真实评测与回归门禁链路.md)及交接结果。

源码必读：`apps/webui/src/App.tsx`、`main.tsx`、`adapter/web-api.ts`，所复用的 UI 组件/路由，commerce API、任务事件和报告渲染实现。实施前确认 App 是否直接复用 Electron 页面，选择最小集成点，不凭目录名假设路由存在。

依赖 03 API 和 04 持久任务通过验收；05 可并行补全，但对外发布前必须通过其门禁。

## 2. 业务结果与范围

保留已有通用聊天入口，增加电商专用案例工作台。首轮只围绕两个业务场景，不搭建通用 BI 和复杂可视化编辑器。

监控采用确定性阈值与完整性规则，触发持久任务后再调用模型。用户反馈进入待复核评测队列，不直接改 Prompt 或训练模型。

## 4. 执行任务

### 06.1：六个必要视图

- [ ] 案例列表：店铺、对象、问题、当前状态、更新时间；权限过滤在服务端。
- [ ] 发起/查看调查：输入范围、待澄清项、进度、错误/预算停止原因、取消；不把首 token 显示为完成。
- [ ] 报告与证据：关键事实、假设、反证、未知项、数据时间；点击数值能到对应证据和口径。
- [ ] 审批：动作前后差异、额度、目标版本、证据时间、风险、报告复核状态、过期时间；提交页面实际看到的 hash。
- [ ] 执行结果：成功、失败、UNKNOWN、等待人工分别呈现；重复点击返回同一业务动作，不重复发起。
- [ ] 反馈：接受/拒绝建议、结论错误、缺少数据、人工纠正；可关联 claim/evidence，提供必要备注。

### 06.2：事件与断线恢复

- [ ] 复用现有事件通道或为 commerce 提供 SSE；事件含稳定 eventId/sequence/taskVersion，客户端按 ID 去重。
- [ ] 重连用 lastEventId 续传，事件超出保留期则回拉当前 snapshot；页面刷新不重新创建任务。
- [ ] 报告、Trace、下载经授权 API 提供，不暴露本机文件路径或可猜测的静态跨租户文件链接。
- [ ] 浏览器只接收可展示摘要，使用安全 Markdown/文本渲染；原始外部文本不得执行 HTML/脚本。
- [ ] 双标签页审批、失效登录、会话切换、错误/空/加载状态可理解；服务端拒绝必须反映到界面。

### 06.3：Monitor / Detect

- [ ] 为广告效率与销量/库存设置可配置阈值、最小样本量、可比时间窗、数据完整性和节假日/促销提示；这是规则扫描，不声称因果检测。
- [ ] 使用 04 持久任务调度扫描；唯一键由 tenant/shop/entity/ruleVersion/window 构成，事务创建异常和任务。
- [ ] 同一异常在冷却期合并到已有 Case，新增证据版本形成追加事件；不能因为每次 snapshotId 变化就重新开单。
- [ ] 严重度升级可重新提醒，但遵守去重与次数限制；数据不完整时记录延后判断原因。
- [ ] 为单租户扫描和模型调用设置配额，避免一次导入大量 SKU 触发成本失控。

### 06.4：案例记忆与反馈闭环

- [ ] 历史案例先按 tenant/shop、对象、异常类型、时间和已复核结果检索，无需先引入向量库。
- [ ] 历史结论带证据和有效期，以“历史参考”注入上下文；当前事实必须重新查询，拒绝跨租户复用。
- [ ] 反馈保存操作人、角色、reportVersion、claimId、意见和时间，重复提交幂等；反馈本身不是已验证事实。
- [ ] 新失败案例进入待复核池，脱敏、明确答案后添加到 05 的 dev/regression；不直接污染冻结 holdout。
- [ ] 展示运营采用/拒绝率时附任务数与定义；不能由点击“采纳”推导实际收入改善。

## 5. 验证矩阵

| 浏览器/后台场景 | 必须观察到 |
| --- | --- |
| 运营登录→调查→证据→审批人批准→测试平台执行 | 两个账号各自权限正确，报告与动作版本一致 |
| NEEDS_DATA / 无需动作 / 模型失败 | 状态和可选下一步明确，不强制审批 |
| 刷新、断网重连、重复点击 | 事件连续或 snapshot 恢复，无重复任务/动作 |
| 双窗口展示不同提案版本 | 旧 hash 审批被拒绝并要求刷新 |
| 过期/拒绝/UNKNOWN | 不误显示成功，人工处理入口可定位 |
| 并发扫描、同窗数据修订 | 一个 Case、可追溯追加证据、不重复提醒 |
| 恶意外部文本、跨租户 URL | 无脚本执行、无越权内容 |
| 错误反馈转评测候选 | 有来源、复核状态，未改动 holdout |

拟新增命令：

```bash
bun run commerce:test:monitoring
bun run commerce:test:feedback
bun run commerce:test:e2e
bun run webui:typecheck
bun run webui:build
```

浏览器自动化默认使用受控模型 transport 和独立测试平台以保证可重复；另跑至少一条真实模型完整 UI 调查作为人工验收，标明两种证据。保留关键页面截图和失败轨迹，使用生成数据。

## 6. 完成门槛与交付证据
