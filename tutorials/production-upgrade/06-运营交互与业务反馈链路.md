状态：CODE_READY / BROWSER_E2E_PENDING / MONITOR_TASK_HANDOFF_PENDING / USER_ACCEPTANCE_PENDING。产物类型：Workflow / Memory / Agent supporting。目标是让不读源码的运营用户完成调查、核查、审批和反馈，并形成 Monitor → Detect → Investigate → Decide → Act 的可见闭环。

## 2. 业务结果与范围

保留已有通用聊天入口，增加电商专用案例工作台。首轮只围绕两个业务场景，不搭建通用 BI 和复杂可视化编辑器。

监控采用确定性阈值与完整性规则，触发持久任务后再调用模型。用户反馈进入待复核评测队列，不直接改 Prompt 或训练模型。

## 4. 执行任务

### 06.1：六个必要视图

- [x] 案例列表：店铺、对象、问题、当前状态、更新时间；权限过滤在服务端。
- [x] 发起/查看调查：输入范围、待澄清项、进度、错误/预算停止原因；不把首 token 显示为完成。取消入口待浏览器 E2E 批次补充。
- [x] 报告与证据：关键事实、假设、未知项、数据时间和证据摘要；证据详情继续走受权 API。
- [x] 审批：参数、目标版本、风险、复核状态、过期时间与页面实际 contentHash 一并展示和提交。
- [x] 执行结果：APPLIED、REJECTED、UNKNOWN、MANUAL_REVIEW 分别呈现；执行由 04 审批 outbox/job 自动触发，不增加绕过策略的页面按钮。
- [x] 反馈：接受/拒绝建议、结论错误、缺少数据、人工纠正；可关联 claim/evidence，提供必要备注。

### 06.2：事件与断线恢复

- [x] commerce 首版使用带稳定 eventId/sequence/taskVersion 的增量读取，并提供聚合 snapshot；浏览器按任务 ID 回拉，不因刷新创建任务。没有宣称 SSE。
- [x] 页面以 snapshotVersion 恢复并轮询增量状态；当前事件不裁剪，因此未实现“超出保留期”分支，后续若增加 retention 必须返回 resetRequired。
- [ ] 报告、Trace、下载经授权 API 提供，不暴露本机文件路径或可猜测的静态跨租户文件链接。
- [ ] 浏览器只接收可展示摘要，使用安全 Markdown/文本渲染；原始外部文本不得执行 HTML/脚本。
- [ ] 双标签页审批、失效登录、会话切换、错误/空/加载状态可理解；服务端拒绝必须反映到界面。

### 06.3：Monitor / Detect

- [x] 为广告效率与销量/库存设置可配置阈值、最小样本量、可比时间窗、数据完整性和节假日/促销提示；原因文本明确这是规则扫描，不声称因果检测。
- [ ] 使用 04 持久任务调度扫描；唯一键由 tenant/shop/entity/ruleVersion/window 构成，事务创建异常和任务。
- [x] 同一异常在冷却期合并到已有 Case，snapshot 重放幂等，新 snapshot 形成 observation；不会因 snapshotId 变化直接开新 Case。
- [x] 严重度升级才增加通知次数；数据不完整生成 DEFERRED Case 与明确原因。
- [x] 单次扫描限制实体数量与新 Case 数量；模型调用仍由 01/04 预算控制。

### 06.4：案例记忆与反馈闭环

- [x] 历史案例按 tenant/shop、对象、异常类型、时间和已复核结果检索，不引入向量库。
- [x] 历史结论带证据和有效期；Repository 只返回同 tenant/shop 且未过期的人工复核记录，调用方仍须重查当前事实。
- [x] 反馈保存操作人、角色、reportVersion、claimId、evidenceId、意见和时间，重复提交幂等；反馈本身不是已验证事实。
- [x] 错误/缺数/纠正反馈进入 PENDING_REVIEW 评测候选；候选投影不含备注正文，不直接改 dev 或冻结 holdout。
- [ ] 展示运营采用/拒绝率时附任务数与定义；不能由点击“采纳”推导实际收入改善。

## 8. 固定设计决策

1. 通用 Agent UI 保持不变，`apps/webui/src/App.tsx` 仅在 `/commerce` 路径选择专用工作台；浏览器用 `/commerce-api` 与宿主 `/api` 隔离。
2. 浏览器只消费 JSON DTO，React 默认文本转义；不渲染报告 Markdown/外部 HTML，不返回本机报告路径。
3. 首版事件恢复使用 3 秒 snapshot 轮询与稳定 eventId/sequence，不在没有流式代理的情况下冒充 SSE。
4. 监控只检测“指标组合满足规则”，原因文本必须保留“需调查、非因果结论”。
5. 反馈必须绑定 report content hash；错误类反馈只进入待复核候选，不自动修改 Prompt、训练数据或 holdout。
6. 案例记忆只有 APPROVER/ADMIN/AUDITOR 可写，运营可在自身 tenant/shop 范围读取未过期的复核结果。

## 9. 输入、输出与接口

| 能力 | 输入 | 输出/失败语义 |
| --- | --- | --- |
| `GET /api/v1/tasks` | 登录身份、limit、before | 服务端按 tenant/shop 过滤的案例摘要；跨租户对象不出现 |
| `GET /api/v1/tasks/:id/snapshot` | taskId | task/run/events/report/reportVersion/proposals/executions 与 snapshotVersion；不可见对象 404 |
| `GET /api/v1/csrf-token` | 有效 HttpOnly session | 轮换后的短期写请求 token；旧 token 立即失效，不返回 session secret |
| `POST /api/v1/feedback` | task/report/version/claim/evidence/kind/notes/idempotencyKey | feedbackId、是否 replay、是否进入 eval candidate；版本陈旧/关联错误拒绝 |
| `GET /api/v1/evaluation-candidates` | audit 权限 | 自身授权店铺的脱敏待复核候选 |
| `MonitorService.scan` | scope、snapshot、窗口、实体指标、规则版本/阈值/配额 | CREATED/MERGED/DUPLICATE/ESCALATED/QUOTA_SUPPRESSED |
| `CaseMemoryRepository.search` | principal、shop、对象、异常类型 | 同租户同店且未过期的 reviewed memory |

监控状态：`OPEN → INVESTIGATING → RESOLVED`；数据不完整进入 `DEFERRED`。本批次实现持久 Case/observation、`attachTask` 契约和状态展示，但广告 Campaign 尚不能无损映射到现有仅含 `skuIds` 的 Investigation scope，因此自动创建调查任务暂不启用，避免把 campaignId 伪装成 skuId。
