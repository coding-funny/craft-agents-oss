# 02：数据接入与证据治理链路

状态：PLANNED。产物类型：External Knowledge / Memory / Workflow。目标是把模型调查建立在有版本、可核查、可更新的经营数据之上，并提供后续服务化共用的 PostgreSQL 存储。

## 1. 必读输入与进入条件

读 [入口](./README.md)、[共享契约](./00-总体设计与共享契约.md)、[01](./01-真实模型与动态调查链路.md)及其实际交接记录。

源码必读：`packages/commerce-agent/src/adapters/fixture-adapter.ts`、`domain/contracts.ts`、`metrics/`、`evidence/evidence-repository.ts`、`storage/database.ts`、`reports/`、`approvals/repository.ts`、`recovery/case-repository.ts`、`tests/adapter.test.ts`、`tests/report.test.ts`。

01 的通用契约和离线回归通过即可启动；01 的真实模型验收缺失单独保留。检查 PostgreSQL 测试环境；实际商家数据无授权时先用明确标记的合成导入文件。

## 2. 业务结果与范围

支持授权经营数据导入、更新、查询与证据追溯。首个实际入口是 CSV/JSON 导出导入；文件是后端受控导入任务，不作为模型任意文件工具。

本轮必做 PostgreSQL Repository 和导入式 Adapter、独立 HTTP 测试数据源，验证分页/限流/增量契约。具备明确平台授权和资料后才增加该平台只读连接器，不在缺少接口事实时假造广告平台已接入。

库存、促销、销售和广告不齐全时允许独立导入并报告完整性；不能通过补零伪造联合诊断所需证据。

## 4. 执行任务

### 02.1：建立异步持久化边界

- [ ] 提取 Evidence/Report/Case/Run/Proposal/Approval/Attempt/Audit Repository 与 UnitOfWork，所有数据库访问显式 await。
- [ ] 创建 PostgreSQL Schema，所有业务记录含 tenant/shop；唯一键、关联键与查询都约束作用域，不仅顶层 Case 带租户。
- [ ] 为旧 SQLite 与 PostgreSQL 运行共用契约测试；权限策略待 03 强化，但作用域不可为空。
- [ ] 提供 schema 版本管理、失败迁移测试和离线导入命令；旧库只读备份，用户明确选择目标新库后迁移。
- [ ] 报告 DB 为主存储，文件为可再生成物；处理落库后文件生成失败。报告旧 Schema/哈希保留对应读取规则。

### 02.2：导入与指标口径

- [ ] 定义 ImportManifest：sourceType、owner/授权说明、tenant/shop、币种/时区、字段映射、导出时间、业务窗口、文件摘要、schemaVersion。
- [ ] 支持订单/退款、库存、促销、商品成本、广告五类记录。未知字段或错误记录进入隔离清单，不能悄悄丢弃后称导入完整。
- [ ] 以来源和原始记录 ID 去重，修订记录保留版本；同一 ID 内容变化是更新，不是新销售。
- [ ] 区分业务时间与采集时间；定义退款归属、取消单、成本、广告归因窗口。多币种不直接相加；聚合金额持续检查安全整数溢出。
- [ ] 游标只在本批数据持久化成功后推进，迟到数据通过重叠回拉窗口/修订版本合并。导入失败可重试且不重复记账。

### 02.3：Adapter、分页与实时性

- [ ] 工具只依赖 CommerceAdapter，切换 Fixture / 导入数据不修改模型 Prompt 中的案例答案。
- [ ] 实现受控 HTTP 测试源，独立进程返回分页、429、重复/乱序数据及游标过期错误，验证 Adapter 合同。
- [ ] 查询固定 snapshot，跨页新增数据不导致同一报告混用版本。缓存 key 包含 tenant/shop/query/snapshot，更新后失效。
- [ ] source capability 明确区分“无记录”“该源不支持”“查询失败”“数据尚未完整”，工具保留 warnings。
- [ ] 对真实授权导出做一次导入与模型调查；未取得数据则保留该外部验收，不将生成数据改名为真实数据。

### 02.4：证据与报告治理

- [ ] 每个指标可追溯原始记录、snapshot、定义版本；报告引用不可被后台覆盖成新数据。
- [ ] 根据指标定义新鲜度和完整性规则；报告生成时固定 asOf，审批/执行前刷新关键对象，过期报告重新调查而非只延长有效期。
- [ ] 扩展硬门禁：跨租户/错时间窗/错单位/快照冲突/指标值篡改必须拒绝。
- [ ] 增加逐 claim 的语义复核：支持、矛盾、证据不足以及证据引用；数值正确但业务解释错误不能只靠禁词正则检测。
- [ ] 明确 Reviewer 超时/不可用时可展示“待复核”报告，但不能自动升级为可执行提案；高风险提案继续要求确定性规则与人审。
- [ ] 启发式置信度重命名或展示为证据充分度，保留旧报告读取；按人工标注评估语义复核误判，禁止宣传消除幻觉。

## 5. 验证矩阵

| 输入/故障 | 期望 |
| --- | --- |
| 同文件导入两次、部分失败后重试 | 行数与指标不翻倍，批次可追溯 |
| 迟到退款、同 ID 修订、乱序库存 | 正确时点结果与版本变化可解释 |
| 成本缺失、广告缺失、币种冲突 | 显式 incomplete/rejected，不变成有效零值 |
| 分页期间新增数据、游标失效 | 保持快照或明确重新查询，不混合证据 |
| 报告引用另一 shop 的证据 | 拒绝且不泄露内容 |
| 数字正确、库存与广告因果解释颠倒 | 语义测试/人工评分能标错，记录误判 |
| PostgreSQL 回滚/重启 | 事务无半写入，重启后产物可读取 |
| 旧 SQLite 报告迁移 | 数量、作用域映射、哈希校验，旧数据仍可读 |

拟新增命令：

```bash
bun run commerce:db:migrate -- --config <test-db-config.json>
bun run commerce:test:storage
bun run commerce:test:imports
bun run commerce:test:evidence
bun run commerce:import -- --manifest <import-manifest.json> --dry-run
bun run commerce:import -- --manifest <import-manifest.json> --apply
```

迁移/导入命令必须检查目标环境；测试脚本只管理明确命名的测试库。新数据库集成测试不得因连接失败静默 skipped。收尾运行电商回归及 01 真模型 smoke（具备配置时）。
