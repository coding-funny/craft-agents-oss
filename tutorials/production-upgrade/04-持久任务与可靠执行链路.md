# 04：持久任务与可靠执行链路

状态：PLANNED。产物类型：Runtime / Memory / Workflow。目标是让调查和动作在进程崩溃、重复投递、网络不确定及并发执行下保持可恢复、可解释。

## 1. 必读输入与进入条件

读 [入口](./README.md)、[共享契约](./00-总体设计与共享契约.md)、[03](./03-身份授权与审批治理链路.md)及其交接。

源码必读：`packages/commerce-agent/src/recovery/`、`execution/`、`approvals/state-machine.ts`、`approvals/repository.ts`、`tests/recovery.test.ts`、`tests/approval-execution.test.ts`、`evals/failure-injection.ts`，以及 01—03 新增的任务/存储/授权代码。

进入条件：PostgreSQL 集成测试通过，03 可信主体与审批策略可调用，01 任务入口可由非 UI 进程驱动。

## 2. 业务结果与范围

支持任务排队、至少两个调查 Worker 竞争、人工等待、取消/超时、断点恢复，以及审批后异步动作和对账。平台动作首轮接独立 HTTP 测试服务，数据与业务库独立，模拟延迟可见和结果丢失。

首轮动作聚焦 ADJUST_AD_BUDGET 与测试工单创建。保留本地 MockExecutor 用于快速回归；网络测试平台是新增验证环境，不能称真实广告平台。

不宣称通用 exactly-once。采用至少一次任务投递、业务幂等、状态条件更新及 UNKNOWN 对账；无法判定的副作用停止自动重发并交人工处理。

## 3. 拟改动位置

| 路径（相对 `packages/commerce-agent/`） | 职责 |
| --- | --- |
| `src/jobs/queue.ts`、`lease.ts`、`worker.ts` | 持久队列、领取、续租与接管 |
| `src/jobs/outbox.ts`、`checkpoints.ts` | 事务事件和可恢复步骤 |
| `src/execution/executor.ts`、`http-executor.ts` | 异步动作协议与 HTTP 实现 |
| `src/execution/reconciliation.ts` | 查询、退避、人工处理 |
| `src/storage/migrations/` | jobs、outbox、leases、checkpoint、远端请求台账 |
| `tests/runtime/`、`tests/execution-http/` | 多进程、网络与崩溃测试 |
| `test-support/platform-server/` | 独立存储的测试平台与故障控制 |

HTTP 调用必须在短事务外；不得将整个 LLM 调查或外部网络调用包在数据库行锁事务内。

## 4. 执行任务

### 04.1：持久队列与并发控制

- [ ] 实现 jobs 表和短事务领取，可使用 `FOR UPDATE SKIP LOCKED`；task/run/attempt 分层，不把同一任务重试伪装成新业务任务。
- [ ] 租约含 owner、leaseUntil、递增 epoch；心跳与完成提交均检查 epoch，失去租约的 Worker 不能覆盖接管者结果。
- [ ] 队列设置 tenant 公平性、每租户/模型并发上限、重试时间、最大次数与人工处理队列，防止一个租户耗尽额度。
- [ ] 应用退出停止领新任务，处理在途取消/交接；数据库断连时不继续执行新副作用。

### 04.2：事务事件、断点与恢复

- [ ] 创建任务、审批状态变化和 Outbox 事件原子提交；派发重复允许，消费方按事件/业务键去重。
- [ ] 持久化模型请求/结果元数据、工具调用/结果、结构化调查状态、report/proposal ID 和配置版本。
- [ ] 工具调用发出但未持久化结果时，只读工具可在预算内重试；模型调用可能重复计费，单独记录不确定 usage，不承诺 token exactly-once。
- [ ] 从最新已提交边界恢复；数据过期或 Prompt/工具版本不兼容时显式刷新/重开 attempt，保留原证据与父子关系。
- [ ] 区分 WAITING_INPUT 与等待审批，进程退出不丢失等待状态；新补充信息经过授权并绑定 taskVersion。

### 04.3：发送前记账与远端幂等

- [ ] 将 ExecutionService 改为 ActionExecutor 端口，禁止耦合具体 MockExecutor；DB 事务只处理本地状态和台账。
- [ ] 审批策略和目标条件通过后，先持久化 requestId/idempotencyKey/参数摘要和执行意图，再发送网络请求。
- [ ] 测试平台支持幂等键和 expectedVersion，重复键不同 payload 拒绝；执行记录存于独立数据库。
- [ ] 覆盖“发送前崩溃”“平台成功但响应丢失”“收到响应尚未记账”“超时后旧 Worker 恢复”各窗口。
- [ ] action 调用不能直接套用只读 ToolRunner 的自动超时重试。executor capabilities 决定能否按相同键安全重发。
- [ ] target 版本校验必须在远端原子执行；只先 GET 检查再无条件写存在竞态，不能计为受控条件更新。

### 04.4：UNKNOWN 与取消

- [ ] Lookup 区分 APPLIED、REJECTED、PENDING、NOT_FOUND、UNAVAILABLE；NOT_FOUND 的权威性和平台可见性窗口在能力契约中显式描述。
- [ ] 非权威 NOT_FOUND/UNAVAILABLE 保持 UNKNOWN，以有上限的退避查询和告警推进，超过期限标记人工处理。
- [ ] 无外部 operationId 时仍可用预先持久化的 requestId/idempotencyKey 查找；不凭本地变量是否赋值判定远端未执行。
- [ ] 用户取消可阻止未发送动作；在途写操作不能简单标 CANCELLED，应继续核实结果。审批撤销与执行争抢用状态/版本条件协调，说明远端已接受后的边界。
- [ ] 如需恢复预算/撤销工单，创建新的补偿提案与审批。记录原动作关联，不自动覆盖原成功记录。

## 5. 验证矩阵

| 故障点 | 观测与硬门槛 |
| --- | --- |
| 两个真实 Worker 领取同任务 | 一个有效租约；旧 epoch 不能提交 |
| Outbox 派发前后杀进程 | 事件不丢失，重复投递不重复业务效果 |
| 调查中断后重启 | 已提交证据/状态复用，过期证据刷新 |
| 远端成功后断开连接 | UNKNOWN；按请求标识查得结果 |
| 远端结果延迟可见 | 暂时 NOT_FOUND 不标 FAILED，不盲重发 |
| 收到成功响应、提交 DB 前 SIGKILL | 接管并对账，只有一次外部业务效果 |
| 丢租约的 Worker 恢复并发发送 | 幂等/目标条件保护；本地 fencing 不被夸大为远端锁 |
| 远端无幂等能力且结果不明 | 禁止自动重发，明确人工处理 |
| 数据库不可用、模型挂起、取消 | 停止新调用/新副作用，保留可恢复状态 |

拟新增命令：

```bash
bun run commerce:worker -- --kind investigate
bun run commerce:worker -- --kind execute
bun run commerce:test:runtime
bun run commerce:test:execution-http
bun run commerce:eval:chaos -- --config <chaos-config.json>
```

故障控制仅暴露于测试环境。测试用真实子进程退出/网络断连与独立平台存储，不只在函数内 throw。全部记录 task/run/proposal/request、进程、注入时点和远端效果计数。

## 6. 完成门槛与交付证据

- [ ] 至少两个 Worker、多进程崩溃及重启测试通过，队列无永久悬挂任务。
- [ ] 所有副作用窗口都有测试；支持幂等的测试平台重复效果数为 0，结果不明的平台不自动重发。
- [ ] UNKNOWN 经查询可恢复或进入明确人工待处理状态；人工等待不计成功。
- [ ] 重试、超时、取消与模型成本的边界明确，等待人工不占执行租约。
- [ ] 输出状态图、事务边界 ADR、故障注入原始轨迹、恢复手册和至少一条完整失败恢复演示。

## 7. 回退、交接与验收记录

回退先停止领取新任务并确认在途请求，再切换兼容版本；不能清空队列或把 UNKNOWN 重置 APPROVED。保留 requestId 与幂等键，切回单 Worker 不改变任务身份。

交给 05：故障套件、真实终态、恢复时间和副作用统计。交给 06：等待/取消/人工处理事件。交给 07：进程启动、健康检查、租约及告警参数。

验收记录：待执行；填写多进程环境、平台能力、注入位置、实际恢复结果和已知无法自动处理的情况。
