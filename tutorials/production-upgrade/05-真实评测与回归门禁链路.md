# 05：真实评测与回归门禁链路

状态：PLANNED。产物类型：Eval。目标是衡量真实模型调查的质量、稳定性、成本和工程边界，形成可复现的比较与发布判断。

## 1. 必读输入与进入条件

读 [入口](./README.md)、[共享契约](./00-总体设计与共享契约.md)、[01](./01-真实模型与动态调查链路.md)和 [04](./04-持久任务与可靠执行链路.md)；读取实际交接中的模型 manifest、数据字典、策略和故障记录。

源码必读：`packages/commerce-agent/evals/runner.ts`、`case-runner.ts`、`scorers.ts`、`baselines.ts`、`failure-injection.ts`、`dataset.jsonl`，以及 `docs/evaluation-report.md`。

本计划从 01 就用于数据/评分设计，不需要等 04 才读取。完整执行与验收依赖 01—04；离线数据整理、评分器和审查流程可提前开展。

## 2. 业务结果与范围

现有 24 条 deterministic regression 单独保留，继续证明工程契约；新建真实模型评测套件，分别回答“调查是否正确”“是否安全结束”“成本和时间如何”“多次结果是否稳定”。

独立测试平台结果只证明工程不变量，不代替模型推理质量。人工/模型评分、模拟/实际数据、单次/多次结果均分栏报告。

## 3. 拟改动位置

| 路径（相对 `packages/commerce-agent/`） | 职责 |
| --- | --- |
| `evals/agent/cases/`、`schemas.ts` | 模型可见输入与受控 gold 定义 |

gold 不放入 MCP 可读目录或 Agent 的自由文件访问范围。命令执行工作目录和工具权限也必须保证这一点，不能仅靠约定文件名。

## 4. 执行任务

### 05.1：分阶段建设数据集

- [ ] 01 的 20 条种子只作 dev；02—04 补数据/权限/恢复案例，最终目标 60 个独立业务任务，40 dev + 20 holdout。
- [ ] 目标覆盖分布：广告异常 12、库存/促销/利润 12、无需行动 8、缺失/冲突/歧义 12、长上下文/多轮补充 8、受攻击/工具故障下调查 8。执行器故障矩阵另统计，不混成同一准确率。
- [ ] 每个任务记录 baseScenarioId、数据来源与许可、问题、可见数据、正确结果允许范围、必要证据、禁止结论/动作、所需澄清及任务难度。
- [ ] 按底层业务事件/数据生成族/实际商家时间窗口分组切分；同一 Fixture 换措辞或改 ID 不算独立 holdout。
- [ ] holdout 不用于调 Prompt、阈值或编写特例。解封后发现系统性问题，可以修复，但下一次独立验证需新保留集或标明已转为回归集。

### 05.2：真实对照与公平条件

- [ ] 保留确定性规则流程作工程对照；新增单轮模型分析与受控多步 Agent 两种真模型路径。
- [ ] 两种模型路径使用相同模型配置、原始数据权限、任务、终态评分和明确成本上限；单轮上下文容纳不了任务时报告不可比，不悄悄截掉关键证据。
- [ ] 规则流程可能无法覆盖全部任务，报告其适用覆盖率，不能把所有不适用任务算规则错误来夸大 Agent 收益。
- [ ] 每个模型任务计划重复 3 次，记录独立 runId；先在 dev 做小批量预算估计，再运行完整套件。60 × 3 × 2 为计划的 360 次模型任务，会产生额外 Reviewer 成本，必须纳入总预算。
- [ ] 无足够预算时输出实际完成数与未完成项，不能把一次成功复制为三次。模型后端不支持固定版本/seed 时明确记录这一限制。

### 05.3：评分与人工标注

- [ ] 数值/单位/证据存在性/范围由独立计算器和固定期望检查，避免直接调用被测诊断函数生成 gold。
- [ ] 结论支持性按 claim 判 supported/contradicted/insufficient；同时记录正确引用但推论不成立的错误。
- [ ] 任务完成判定检查落库报告、必要证据、未知项、动作合法性和业务终态，而非模型自述。
- [ ] 对 NEEDS_DATA、澄清和“无需行动”给予正确评价；无谓拒答也计入失败，避免通过总是拒绝提高安全分数。
- [ ] 人工复核全部 holdout 的关键结论及全部高风险/分歧样例；标注人数量如实记录。只有一人时报告单人偏差，不写双人一致性。
- [ ] LLM-as-Judge 输出结构化理由与证据，固定版本/Prompt；与人工结果比较一致性，不能作唯一发布标准。

### 05.4：效果、成本与消融

- [ ] 每项公布分子、分母、适用样本和缺失数量；工具路径允许多个正确方案，不要求与一条硬编码轨迹完全一致。
- [ ] 统计成功任务成本、所有尝试成本、token、工具次数、修复次数、队列等待与实际执行耗时；缓存 token 和估算价格单独标识。
- [ ] 分任务报告多次成功比例、全部重复都成功的稳定性、失败类型；可给置信区间，但不把同任务重复次数当独立业务样本。
- [ ] 在隔离测试环境做上下文压缩、SOP、语义复核、证据门禁等消融。真实关闭相关机制再运行，不以手工构造 counterfactual 分数冒充实验。
- [ ] 移除权限/幂等只允许对隔离测试平台做故障演练，不在真实账户或正常运行模式开放“关闭安全”开关。

### 05.5：定义并验证发布门禁

- [ ] 先在 dev 校准并固定 release-policy，再看 holdout；版本变更留记录，不能因为看到失败而临时放宽。
- [ ] 硬门禁：权限越界/未审批执行/受支持幂等平台的重复副作用为 0；门禁接受的报告关键数字全部可重算；故障矩阵无未解释悬挂状态。
- [ ] 初始质量候选目标：holdout 任务完成率至少 80%，相同任务三次全部成功比例至少 70%；这些是待 dev 校准的目标，非已有结果，也不代表生产可靠性承诺。
- [ ] 多步 Agent 与单轮方案给出质量—成本比较；若没有观察到收益，分析在哪类任务适合规则/单轮/多步并调整路由，不能编造提升。
- [ ] 延迟、成本上限按实际模型和部署环境预先写入配置，再在 07 运行环境复测。

## 5. 验证与命令

拟新增命令（01 已建立的 smoke 命令在本链路扩展）：

```bash
bun run commerce:eval:validate
bun run commerce:test:eval-agent
bun run commerce:eval:agent -- --suite dev --config <eval-config.json>
bun run commerce:eval:agent -- --suite holdout --config <locked-eval-config.json>
bun run commerce:eval:compare -- --runs <run-manifest-list.json>
bun run commerce:eval:gate -- --report <evaluation-report.json>
```

验证数据切分交集、重复族、gold 泄漏、评分器恶意/错误输入、提供方失败、usage 缺失与预算中断。评分器用明确的正负样例测试，不只测试输出格式。

CI 默认运行确定性回归和评分器；真模型回放在有凭证且有预算的独立 job 运行。缺失凭证时 job 明确 pending/skipped，并使需要真模型结果的发布门禁不能通过。

## 6. 完成门槛与交付证据

- [ ] 60 个独立任务目标、切分与评测配置冻结；未达到时记录重规划理由，不虚报样本。
- [ ] 两种真模型路径、多次运行、原始 Trace 和费用明细可对应；规则基线覆盖率清楚。
- [ ] 人工复核、评分器反例、消融和失败分析齐全。
- [ ] 预先固定的发布门禁通过；若模型质量达不到则持续修正 dev 或明确阻塞发布，不能用工程测试数抵替。
- [ ] 输出评测报告、失败分类、质量/成本对照、数据与模型限制，替换后续交付中不准确的模型效果措辞。

## 7. 回退、交接与验收记录

保留上一个通过门禁的模型/Prompt/工具配置组合。新配置失败时回退对应版本，不删除失败结果。回退 Prompt 不意味着可恢复旧数据权限，授权检查始终使用当前规则。

交给 06：人工反馈字段、失败分类、最需要展示的证据。交给 07：可机器执行的 release-policy、冻结数据版本和比较基线。

验收记录：待执行；填写真实样本/运行数、模型标识、人工复核范围、费用、门禁结果和报告路径。
