6. 明确无需行动的报告允许空 recommendations；报告存在不意味着有动作建议，更不意味着执行。

## 9. 输入、输出与接口契约

以下 TypeScript 为拟实现的公共契约，不是当前代码。Zod Schema 为运行时唯一解析入口，生成模型工具 JSON Schema 时保持一致。

### 9.1 输入分层

```ts
type TimeWindow = { start: string; end: string; timezone: string };
type InvestigationInput = {
  schemaVersion: 1;
  question: string;
  scope?: {
    shopId?: string;
    skuIds?: string[];
    baselineWindow?: TimeWindow;
    currentWindow?: TimeWindow;
    currency?: 'CNY';
  };
};

type PrincipalContext = {
  actorId: string;
  tenantId: string;
  allowedShopIds: readonly string[];
  permissions: readonly ('investigate' | 'read_evidence' | 'read_report')[];
  authSource: 'local-fixture'; // 03 扩展；01 不能自称真实登录
};

type InvestigationTask = {
  schemaVersion: 1;
  taskId: string;
  version: number;
  tenantId: string;
  requestedBy: string;
  input: InvestigationInput;
  resolvedScope?: Required<NonNullable<InvestigationInput['scope']>>;
  asOf: string;
  fixtureDigest: string;
  createdAt: string;
};
```

输入规则：question trim 后 1—8000 字符；skuIds 去重后 1—20 个；不接收 actorId/tenantId/runId/traceId/任意工具名/文件路径等额外字段。时间为带 offset 的 ISO 时间，start < end，baseline 结束不晚于 current 开始，时区一致且支持；两个窗口可比性按日历日而非错误地固定 24 小时处理。当前 CNY 单币种，金额仍使用安全整数最小货币单位。

格式非法属于 INVALID_ARGUMENT，启动前退出且不发模型请求；格式合法但必需范围缺失进入 WAITING_INPUT。问题出现与显式 scope 冲突时澄清，模型不能自行扩展 shop。可信身份、数据目录、数据库路径、model connection、asOf 和预算都来自宿主配置，不来自模型或不可信任务 JSON。

### 9.2 输出与错误

```ts
type RunStatus = 'QUEUED' | 'RUNNING' | 'WAITING_INPUT'
  | 'REPORT_READY' | 'FAILED' | 'CANCELLED' | 'TIMED_OUT';
type InvestigationResult = {
  schemaVersion: 1;
  taskId: string;
  runId: string;
  traceId: string;
  status: RunStatus;
  report?: { reportId: string; status: 'RESOLVED' | 'NEEDS_DATA' | 'UNRESOLVED' };
  clarification?: {
    requestId: string;
    expectedTaskVersion: number;
    fields: string[];
    question: string;
  };
  completionReason: string;
  error?: { code: string; retryable: boolean; message: string };
  manifestId: string;
};
```

通过 discriminated union 强制约束：REPORT_READY 必须有 report；WAITING_INPUT 必须有 clarification；其他状态不能伪装带成功报告。候选/孤立 reportId 可以进审计事件，但不进入成功结果。错误消息脱敏，不含提供方凭据、原始请求头、文件系统内部细节。

固定错误码：`INVALID_ARGUMENT`、`SCOPE_DENIED`、`TOOL_NOT_ALLOWED`、`TOOL_SCHEMA_INVALID`、`PROVIDER_UNAVAILABLE`、`MODEL_PROTOCOL_ERROR`、`CONTEXT_LIMIT`、`BUDGET_EXCEEDED`、`LOOP_DETECTED`、`REPORT_NOT_VALIDATED`、`STORAGE_UNAVAILABLE`、`PROCESS_INTERRUPTED`；领域现有错误经映射保留 originalCode。SCOPE_DENIED/越权工具直接结束，不让模型通过反复变形探测。

### 9.3 单次模型生成端口

```ts
interface ModelTurnPort {
  describe(): {
    driver: string;
    modelId: string;
    modelVersion?: string;
    supportsTools: boolean;
    supportsAbort: boolean;
    usageMode: 'actual' | 'estimated' | 'unknown';
  };
  generate(request: ModelTurnRequest, signal: AbortSignal): AsyncIterable<ModelEvent>;
  close(): Promise<void>;
}

type ModelEvent =
  | { type: 'text_delta'; text: string }
  | { type: 'turn_complete'; turn: CompletedTurn }
  | { type: 'turn_error'; code: string; usage?: UsageRecord };

type CompletedTurn = {
  requestId: string;
  text: string;
  toolCalls: Array<{ callId: string; name: string; arguments: unknown }>;
  stopReason: 'stop' | 'tool_use' | 'length';
  usage: UsageRecord;
};
```

`ModelTurnRequest` 包含 messages、systemPrompt、工具 Schema、maxOutputTokens、提供方配置引用；不包含执行工具的函数。`UsageRecord` 分开记录 input/output/cacheRead/cacheWrite/reasoning、计数来源、价格版本与费用估算；reasoning 若已包含在 output 中不得重复相加。

驱动只返回模型建议，不执行工具。只处理完成的 toolCalls；流式参数片段、工具调用开始事件、length 截断回复都不可触发业务工具。01 不启用 deferred/background 模型请求，收到无法同步完成的提供方模式时明确报不支持。

FakeModelTurnPort 仅在显式测试模式使用，可脚本化生成部分流、错误、请求与 usage；真模型测试必须使用 LiveModelTurnPort 并记录来源，禁止替换成同名 mock。

### 9.4 工具接口与作用域

领域工具白名单固定为：`query_sales`、`query_inventory`、`query_promotions`、`query_ads`、`compute_margin`、`get_evidence`、`validate_report`。底层 queryProducts 能力用于毛利计算，但不额外暴露为模型工具。

本地控制工具：

- `record_investigation`：写入简短步骤、假设、反证和缺失项；引用 evidenceId 必须属于当前 task 的可见证据。没有证据的内容只能为假设，不能借该工具晋升为事实。
- `request_clarification`：申请缺失 SKU、日期或问题澄清；不能申请更换 tenant、赋予权限或更改预算，成功后暂停本次 Run。

```ts
interface ScopedToolDispatcher {
  definitions(): ReadonlyArray<ToolDefinition>;
  dispatch(call: CompletedToolCall, context: TrustedRunContext): Promise<ToolResult>;
  close(): Promise<void>;
}

interface CommerceAdapter {
  querySales(query: ScopedQuery, signal: AbortSignal): Promise<SalesQueryResult>;
  queryInventory(query: ScopedQuery, signal: AbortSignal): Promise<InventoryQueryResult>;
  queryPromotions(query: ScopedQuery, signal: AbortSignal): Promise<PromotionQueryResult>;
  queryAds(query: ScopedQuery, signal: AbortSignal): Promise<AdsQueryResult>;
  queryProducts(query: ScopedQuery, signal: AbortSignal): Promise<ProductsQueryResult>;
}
```

五个结果类型从 B00 实际领域契约提取，不能以 any/unknown 代替领域输出校验。ScopedQuery 在域内为 camelCase；现有 MCP snake_case 在边界转换，禁止两套 Schema 漂移。01 返回 source/status/warnings/evidence 和不可变 fixtureDigest；数据源完整 snapshot/增量协议由 02 增补。

模型参数不携带身份、数据库路径、fixtureDir。工具所需 shop/run/case/trace/asOf/currency 由 dispatcher 根据可信 task 注入；模型若夹带保留字段直接拒绝，不能让它覆盖。查询窗口必须落在已批准的两个窗口内，SKU 为批准集合子集，时间拓宽只能经用户澄清后创建新的 taskVersion。

get_evidence 只能访问本任务产生并登记的证据：同时核对 store 命名空间、shop、fixtureDigest 与 evidenceRefs。01 使用独立 run/task 作用域限制，不把“每个 task 一个 SQLite 文件”当真实多租户认证。

listTools 后按显式白名单取交集，任何执行仍二次检查；未知工具不能通过去前缀、模糊匹配或“alias”穿透。stdio 进程 env 只包含显式路径/运行所需项，不能靠不完整凭据黑名单隔离。

### 9.5 工作状态、存储与事件

`InvestigationState` 保存 scope、步骤（pending/done/blocked）、事实引用、候选假设、反证、缺失数据、工具结果索引和调查摘要。只有工具/校验器可生成已确认事实；模型生成的摘要不覆盖原始 Evidence。

```ts
interface InvestigationRepository {
  createTask(task: InvestigationTask, budget: BudgetConfig): Promise<void>;
  createRun(taskId: string, expectedVersion: number): Promise<RunRecord>;
  appendEvent(event: RunEvent): Promise<void>;
  checkpoint(input: CheckpointWrite): Promise<void>;
  settleBudget(input: BudgetSettlement): Promise<void>;
  complete(input: RunCompletion): Promise<InvestigationResult>;
  applyClarification(input: ClarificationAnswer): Promise<InvestigationTask>;
  readRun(runId: string): Promise<RunRecord>;
}
```

新表与现有 Case 隔离，拟新增：

| 表 | 主键/约束 | 关键数据 |
| --- | --- | --- |
| `investigation_tasks` | task_id；version 条件更新 | tenant/shop/actor、input/resolved scope、fixtureDigest、taskBudget 累计 |
| `investigation_runs` | run_id；task_id+attempt 唯一 | status、version、parentRunId、deadline、manifest、report/clarification 引用 |
| `investigation_events` | run_id+sequence 唯一 | eventId、type、time、safe payload、tool/model call ID |
| `investigation_checkpoints` | run_id+checkpoint_no 唯一 | 状态、消息引用、证据索引、预算摘要 |
| `investigation_budget_entries` | reservation_id 唯一 | request/attempt、预留上界、实际/估算 usage、settlement 状态 |

迁移采用 `user_version` 或独立 migrations 表记录，只新增表/索引；async Repository 的内部 SQLite 事务体保持同步，不把 async 函数直接交给 bun:sqlite transaction。完成状态、完成事件与 canonical manifest 同事务；JSONL/Markdown 导出为派生文件，失败标记 exportPending 并可重导。

事件类型至少包含 TASK_CREATED、RUN_STARTED、MODEL_REQUESTED、MODEL_COMPLETED、MODEL_FAILED、TOOL_REQUESTED、TOOL_COMPLETED、TOOL_REJECTED、STATE_UPDATED、CONTEXT_COMPACTED、BUDGET_RESERVED、BUDGET_SETTLED、REPORT_REJECTED、REPORT_ACCEPTED、CLARIFICATION_REQUESTED、RUN_COMPLETED。

每条事件携带 taskId/runId/traceId/sequence/time；stdout 不输出这些事件，仅输出最终 JSON；脱敏进度写 stderr。事件失败不能静默忽略后仍返回成功。

## 10. 状态机、Loop 与预算算法

### 10.1 状态迁移

| 当前状态 | 触发条件 | 下一状态 | 原子保存内容 |
| --- | --- | --- | --- |
| QUEUED | 身份、配置、预算预检通过 | RUNNING | start event、attempt、deadline |
| QUEUED / RUNNING | 合法任务缺必要范围，或 request_clarification 通过 | WAITING_INPUT | 问题、缺失字段、expectedTaskVersion |
| RUNNING | validate_report 成功且 Repository 回读/作用域核验通过 | REPORT_READY | reportId、报告状态、manifest、完成事件 |
| RUNNING | 预算/循环/越权/协议/持久化等不可恢复错误 | FAILED | 明确 errorCode、最后 checkpoint |
| QUEUED / RUNNING | 外部取消在最终提交前生效 | CANCELLED | cancel reason、已发生调用的 usage |
| QUEUED / RUNNING | deadline 到达 | TIMED_OUT | timeout event、预算结算或未决预留 |
| WAITING_INPUT | 用户合法补充并通过 version 校验 | 旧 Run 不变；创建新 Run 的 QUEUED | taskVersion+1、parentRunId、答复引用 |

终态不可原地回 RUNNING。补充答案不接受 tenant/actor/budget 注入；累计费用和调用预算属于 task，创建新 Run 不重置余额。新的运行 deadline 可以重设，费用/调用计数不能清零。REPORT_READY 与取消同时发生以首次成功的状态条件更新为准，晚到事件只审计，不覆盖终态。

进程崩溃后 01 不自动重放未完成 Loop。重新读取 RUNNING 时标记可检查的 PROCESS_INTERRUPTED（须先确认旧进程已退出），保留证据与台账；自动恢复在 04 实现。本链路的“恢复”只覆盖 WAITING_INPUT 的显式继续与 MCP 生命周期，不扩大为分布式恢复。

### 10.2 Runner 顺序

1. 解析外部 input，构建可信 task/scope；不完整则落 WAITING_INPUT，禁止先查询“所有店铺”来补充。
2. 创建 run，校验模型/Fixture/Schema/Prompt 配置，连接 MCP，裁剪工具，加载固定 SOP。
3. 根据结构化状态构建上下文；检测 token 上界与预算，记录预留后调用一次模型。
4. 等到 turn_complete 后结算 usage，检查 stopReason、完整工具参数、唯一 callId 和本轮调用集。
5. 先整体检查本轮作用域、调用数量、预算和工具组合，再执行。任一越权调用则整轮不派发。
6. 普通只读查询最多并发 2 个；完成结果按原 call 顺序回填，事件允许反映真实结束顺序。每个 toolCall 恰有一个对应 ToolResult。
7. 控制工具、validate_report 必须独占一个模型回合；与查询混合则整轮拒绝为可修复协议错误，避免部分执行后提前结束。
8. 保存工具结果索引与工作状态；可恢复错误作为结构化 ToolResult 交模型处理，受到剩余预算约束。
9. 报告校验通过后 Runner 从 Repository 回读，检查当前 task/run/scope/fixtureDigest，提交 REPORT_READY；无需再让模型“确认完成”。
10. 无工具且只有“完成了”文本：反馈一次 REPORT_NOT_VALIDATED，下一回合仍如此则 FAILED。上下文/预算不足不额外补救调用。
11. finally 中取消未完成请求、结算已知 usage、关闭 MCP/模型资源。晚到回调不能改变终态或启动新工具。

### 10.3 预算配置与算法

开发起始默认值如下，均为计划配置，可在测试证明不合理后版本化调整；不是已测性能或费用承诺。

| 参数 | 起始值 | 计数含义 |
| --- | --- | --- |
| maxSteps | 8 | 已完成模型回合；修复回合计入 |
| maxModelRequests | 10 | 所有发出的模型请求，包括重试 |
| maxToolCalls | 16 | 通过预检并获准的逻辑调用；缓存命中/控制工具亦计入 |
| maxToolAttempts | 24 | MCP 实际请求次数，包括 ToolRunner 内部重试 |
| maxParallelTools | 2 | 只读查询；控制/报告工具独占 |
| maxReportRepairs | 2 | 模型提交无效报告后的额外修复机会 |
| maxContextInputTokens | 12000 | 单回合输入上界 |
| maxOutputTokensPerRequest | 2048 | 单次输出上限，包括可计费 reasoning 的提供方约束 |
| maxTotalInputTokens / maxTotalOutputTokens | 48000 / 12000 | task 累计，重试与澄清继续共享 |
| runTimeoutMs / toolTimeoutMs | 120000 / 10000 | 端到端 / 单次工具，上层更短 deadline 优先 |
| maxEstimatedCostMicros | live 必填，无默认无限值 | USD 百万分之一单位；priceVersion 必填 |

预算操作为 `reserve → dispatch → settle`。费用上界来自输入估计上界与本次最大输出、固定价格表；采用整数计费单位向上取整，避免浮点误差。并发工具/请求必须先原子预留，不能各自读取同一余额后越额执行。

没有可信 tokenizer/上界时，驱动必须提供经过验证的保守估计策略；无法给出时 live preflight 不通过。缺 usage 或响应丢失时，保留预留作为保守消耗并标 estimated/unknown，不释放为零。Provider 内部透明重试无法观测/关闭时，不宣称严格请求数控制，必须在 B02 更换可控路径或记录阻塞。

最大金额是本应用在已声明计费模型下的估算上限，不能保证第三方实际账单绝不超出。观察到实际 usage 超过预留时记录偏差、停止后续调用，检查计费/长度模型，不通过继续派发掩盖偏差。

只读工具重试由 ToolRunner 一层管理，最多 2 次尝试，瞬态 429/timeout 才重试；每次开始前从统一 BudgetLedger 领取 attempt。模型每请求最多 1 次额外重试，同样计费、受 deadline 限制。禁止 dispatcher 与 SDK 多层叠加重试。

### 10.4 上下文与循环检测

按 system/SOP → 可信范围与约束 → 结构化调查状态 → 最近完整模型/工具回合构建上下文。压缩使用确定性状态与引用摘要，01 不另起无预算的摘要模型。

保留最近 2 个完整回合；更早工具结果压为 evidenceRefs、数据状态、指标摘要和错误码。不能拆断 assistant toolCall 与 toolResult 配对；反证、缺失数据、允许范围和已有报告拒绝原因不得被裁掉。仍过大时返回 CONTEXT_LIMIT 或由模型分页查询，不静默丢关键约束。

调用指纹由 toolName + 规范化业务参数 + task scope + fixtureDigest 构成，排除 run/trace/callId。参数字段排序/无语义数组排序规则明确。成功只读结果可在同一 task 内复用；遇到瞬态失败不缓存。连续 3 次无新信息的相同请求触发 LOOP_DETECTED；新 cursor、窗口或快照必须改变指纹，不能误判合法分页。

## 13. 文件清单、命令、样例与评测输入

### 13.1 修改边界

本链路主要新增 `packages/commerce-agent/src/{contracts,agent,config}`、专用 investigation Repository、`tests/agent`、`evals/agent`、`docs/implementation/01` 和无密钥 examples。基础 commerce 包当前缺失，B00 不通过不能将所有路径当“局部修改”。

允许必要地修改 FixtureAdapter 类型、工具依赖、ToolRunner attempt hook、Report 的空建议校验、包与根 scripts。shared 只允许经 ADR 说明的 MCP envPolicy 最小变更及其回归。默认不改 `packages/core/src/types/index.ts`、SessionManager、Electron、全局 coding Agent Prompt、全局权限规则及用户已有暂存内容。

### 13.2 脚本与退出码

新增根 scripts 指向包内相同名字的命令；先实现脚本再执行。拟提供：

```bash
bun run commerce:test:agent
bun run commerce:test:agent:contracts
bun run commerce:test:agent:mcp
bun run commerce:investigate -- --input examples/investigation/ads.json --config examples/investigation/local.fake.json
bun run commerce:investigate -- --continue-task <task-id> --answers <answers.json> --config <config.json>
bun run commerce:investigation:status -- --run <run-id> --config <config.json>
bun run commerce:eval:agent -- --suite smoke --config <live-eval-config.json>
```

调查 CLI exit code：0=REPORT_READY（包括有效 NEEDS_DATA 报告）；2=WAITING_INPUT；1=FAILED/配置或存储错误；124=TIMED_OUT；130=CANCELLED。eval 命令按 case.expected 评分，不简单把所有非0解释为模型错误；配置/基础设施异常仍使评测进程失败。

run status 是只读命令，不唤起模型、不自动重试历史Run。最终JSON可定位 manifestId；初始化前配置错误无法创建run时输出独立 `{error:{code,message}}`，不得伪造runId或持久化状态。

### 13.3 输入示例

```json
{
  "schemaVersion": 1,
  "question": "调查 SKU-C 最近一周广告效率下降的原因，检查库存和促销等备选解释；证据不足时说明缺失信息。",
  "scope": {
    "shopId": "demo-shop",
    "skuIds": ["SKU-C"],
    "baselineWindow": {"start": "2026-09-01T00:00:00+08:00", "end": "2026-09-08T00:00:00+08:00", "timezone": "Asia/Shanghai"},
    "currentWindow": {"start": "2026-09-08T00:00:00+08:00", "end": "2026-09-15T00:00:00+08:00", "timezone": "Asia/Shanghai"},
    "currency": "CNY"
  }
}
```

这是输入格式示例，不宣称当前目录已有对应SKU数据。B00/B07 应建立匹配的原始记录；gold 不放在该输入文件或 Skill 中。

运行配置至少包含 dataMode=fixture、modelMode=fake/live、modelConnectionRef、trustedLocalPrincipal、fixtureDir、dbPath、artifactDir、asOf、budget、价格版本、SOP版本。CLI路径由操作者指定并校验，只传给宿主；模型不可读取任意目录。live-eval配置另有 suite 总任务数、并发、总费用上限，不只有单任务预算。

### 13.4 20 条开发种子定义

| ID | 分类 | 输入变化/预期考点 |
| --- | --- | --- |
| normal-01 | 无需行动 | 指标稳定、证据完整；无动作报告 |
| normal-02 | 无需行动 | 同比可比窗口正常波动；不能硬造根因 |
| normal-03 | 无需行动 | 销售增长、贡献率不降、库存正常；无强制预算调整 |
| ads-01 | 广告 | 花费/点击增加、转化下降；检查库存与促销反证 |
| ads-02 | 广告 | CPC上升而CVR稳定；区分流量成本与转化变化 |
| ads-03 | 广告 | 库存为零期间ROAS下滑；不能直接归为素材问题 |
| ads-04 | 广告 | 归因窗口未结束；返回不确定性 |
| ads-05 | 广告 | 促销结束与CVR下降同现；说明关联而非因果证明 |
| commerce-01 | 库存/促销 | 缺货与销量下跌，促销稳定 |
| commerce-02 | 库存/促销 | 促销拉动销量但贡献率下降 |
| commerce-03 | 库存/促销 | 退款跨期造成净销售变化；核对口径 |
| commerce-04 | 库存/促销 | 多SKU表现相反；不能只用总量概括每个SKU |
| commerce-05 | 库存/促销 | 取消单/重复记录；确定性指标不重复计入 |
| uncertain-01 | 缺失/歧义 | SKU或日期缺失；WAITING_INPUT |
| uncertain-02 | 缺失/歧义 | 商品成本缺失；毛利不能按零成本计算 |
| uncertain-03 | 缺失/歧义 | 库存快照相互冲突；保留反证 |
| uncertain-04 | 缺失/歧义 | 问题与显式时间范围冲突；请求澄清 |
| failure-01 | 工具/格式 | 第一次广告查询429后成功；计入重试预算 |
| failure-02 | 工具/格式 | 工具缺失/暂不可用；解释缺失，不能编数据 |
| failure-03 | 工具/格式 | 一次报告数值错误；有限修复后门禁验证 |

smoke 固定为 normal-01、ads-01、commerce-01、uncertain-02、failure-01。failure-03 的格式错误通过 scripted 测试确定性覆盖；live 评测只观察实际模型行为，不强迫模型犯错来制造成功修复故事。

数据源可以是合成数据，但不同任务的生成依据、原始字段、数据版本和预期约束需明确。normal-02 的“同比”仅指提供的可比基线，不自动引入未提供的上一年数据。20条均为 dev，不做独立泛化准确率声明。
