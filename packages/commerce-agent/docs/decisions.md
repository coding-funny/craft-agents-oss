# 关键技术决策

## 1. 先用固定 Fixture，不先接真实平台

目的是让金额口径、时间边界、退款跨期和故障路径可重复。代价是不能据此声称生产效果；真实 Adapter 被保留为后续扩展点。

## 2. 报告门禁放在服务端

Prompt 规则只能降低错误概率，无法形成安全边界。服务端会解析 Evidence、重算 KPI、核对 baseline/current 周期并验证内容哈希，因此模型即使输出结构合法但数值错误的报告也会被拒绝。

## 3. 模型只能创建 Proposal

`create_proposal` 和 `get_proposal` 可由 MCP 调用；批准、拒绝、执行和对账只存在于操作员 CLI。这样把“提出建议”和“授权副作用”分成两个身份域。

## 4. Proposal 不可变，审批绑定内容哈希

审批记录保存 Proposal 的 SHA-256 内容摘要。执行前重新计算；参数、有效期或目标对象被修改后，旧审批不能继续使用。需要改变动作时应生成新报告/Proposal，而不是原地编辑。

## 5. SQLite 条件迁移与幂等台账

状态迁移使用事务和带原状态条件的更新；执行尝试和 Mock Operation 对幂等键建立唯一约束。进程级锁不是正确性前提，第二个执行者会看到竞争失败或首个结果。

## 6. UNKNOWN 优先于盲目重试

副作用发生后若响应丢失，本地不能判断成功与否。系统记录外部操作 ID 并进入 `UNKNOWN`，后续通过只读查询/台账对账。自动重试会带来重复调预算或重复补货的风险。

## 7. Case 恢复使用独立 session 状态

报告、Proposal 与执行状态各自解决局部持久化，但无法说明一次业务任务恢复到哪一步。`case_runs` 把 session、父子 Trace、Report、Proposal 和终态连接起来，恢复时从已完成边界继续。

## 8. 确定性评测与模型评测分开

当前 24 条数据集验证代码契约和安全不变量；没有调用外部 LLM，因此不报告模型准确率、token 成本或提示词泛化。未来模型回放必须固定模型版本、提示词、预算和保留集，并单独记录波动。
