# 大厂 Agent 开发面试追问

## 为什么不用 Prompt 约束模型不要乱写数字？

Prompt 不是安全边界。报告服务根据 Evidence 中的原始销售、库存和广告记录重新计算 KPI，还核对周期、币种和单位；错误报告在进入 Proposal 前被拒绝。

## Tool Calling 做了哪些工程治理？

输入采用严格 Zod Schema；Tool Runner 统一 Trace、超时、429 指数退避预算、敏感参数摘要和结果截断；工具只能访问绑定店铺和固定数据目录。

## Context Engineering 体现在哪里？

Skill 固化“销量检测→库存/促销/毛利/广告补证→冲突/未知→报告”的 SOP，并限制工具白名单。业务事实不写进 Prompt，而由工具与 Evidence 注入。

## 为什么 Proposal 和审批要分开？

Proposal 是模型提出的候选动作，不是授权。审批由模型外 CLI 完成，并绑定 actor、理由、过期时间和内容哈希；模型工具集中不存在 approve/execute。

## 并发执行如何避免重复副作用？

先用条件更新争抢 `APPROVED -> EXECUTING`，再通过执行尝试和外部操作台账的唯一幂等键约束。后续请求返回首次结果，不再次修改 Mock 状态。

## 为什么需要 UNKNOWN？

调用方超时不等于远端失败。若写入已发生但响应丢失，自动重试可能重复调预算。系统保留 UNKNOWN，再通过外部操作 ID/台账对账到 SUCCEEDED 或 FAILED。

## 进程重启后怎么恢复？

Case Repository 保存 session、当前状态、Report/Proposal ID、恢复 Trace 与 parent Trace。Runner 先读取持久化边界：已有报告不再诊断，已有 Proposal 不再创建，已有成功执行直接复用。

## 评测为什么不是一个总准确率？

不同能力的分母不同。报告分别统计工具选择、参数、Evidence、数值、审批安全、幂等和恢复；这样能定位失败层，避免用一个小样本总分掩盖安全问题。

## 24/24 能说明什么？

只能说明固定 Fixture 上的 24 条确定性回归全部通过，不能说明模型泛化或线上效果。外部 LLM 回放仍需固定模型/提示词/预算并保留未参与调试的集合。

## 如果接入真实淘宝/抖音广告平台，先改什么？

替换 Adapter 和 Mock Executor，同时补 OAuth/密钥托管、RBAC、限流、平台版本号、外部幂等键、对账查询、告警和人工补偿；报告与审批契约可以复用，但不能直接宣称达到生产要求。

## 当前最大不足是什么？

没有真实平台和外部模型运行数据；SQLite 是单机原型；没有多租户、生产可观测性、自动补偿和长期数据时效策略。这些均在项目材料中显式降级。
